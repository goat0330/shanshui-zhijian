# 遥感能力提升路线图

## 1. 当前问题定义

当前 Pipeline 解决的是：

> 在重庆多云环境中，利用 Sentinel-1 双时相 SAR 生成水面变化候选。

它还不是完整的“水域综合异常识别”。下一步不能直接跳到复杂模型，而要依次解决：

1. 真值；
2. 数据质量；
3. 多时相稳健性；
4. 候选质量；
5. 官方任务适配。

## 2. 第一优先级：把结果变成可衡量 Baseline

### RS-01 人工验证集

在 QGIS 建立 GeoPackage：

```text
validation.gpkg
├─ water_polygons
├─ change_polygons
├─ no_change_polygons
├─ uncertain_polygons
└─ scene_slices
```

字段至少包括：

```text
sample_id
label
confidence
scene_type
source
reviewer
reviewed_at
notes
```

标注 20—50 个样区，覆盖稳定水面、岸线、桥梁、船只、阴影、城市强散射和真实变化。

### RS-02 评测脚本

输出：

- pixel-level Precision/Recall/F1/IoU；
- polygon-level Precision/Recall；
- 每平方公里误报数；
- Top-20/50 候选有效率；
- 按场景切片指标；
- Bad Case GeoJSON 与缩略图。

验收标准不是追求某个高分，而是同一 Run 可重复得到同一报告。

## 3. 第二优先级：修复数据和质量问题

### 3.1 S1 轨道一致性

保证比较影像具有：

- 相同升/降轨；
- 相同相对轨道；
- 相近入射角；
- 相近合成策略；
- 无混用不同处理口径。

将这些信息写入 Asset 和 Run Manifest。

### 3.2 地形影响

重庆山地环境必须加入：

- DEM 坡度；
- layover/shadow 质量掩膜；
- 山地与城市切片；
- 候选质量降级，而不是简单全部删除。

候选应同时输出：

```text
model_confidence
data_quality
terrain_risk
```

### 3.3 斑点与边缘噪声

A/B 比较：

- 不滤波；
- Lee；
- refined Lee 或其他稳定方案；
- 不同窗口。

评价边界保持、细小水体、误报和运行时间，不凭视觉主观决定。

## 4. 第三优先级：从双时相升级为多时相

双时相容易把水位、船只、风浪和偶然噪声当作变化。

建议：

```text
历史 3—6 景
→ 每像元 median / percentile
→ IQR 或 MAD 稳定度
→ 当前时段合成
→ 标准化变化分数
→ 连续出现门禁
```

优先实现：

- 历史水体出现频率；
- 当前变化持续次数；
- 新增/消失水体分开；
- 一次突变与持续变化分开；
- 月度窗口和旬度窗口 A/B。

## 5. 第四优先级：S1 特征与分区阈值

比较：

- VV；
- VH；
- VV/VH；
- VV−VH；
- T1/T2 差值；
- 稳健 z-score；
- 局部纹理。

阈值不应只有一个全 AOI Otsu。至少对比：

- 全局阈值；
- 分河段阈值；
- 滑窗局部阈值；
- 稳定水体先验约束；
- 城市/山地不同阈值。

## 6. 第五优先级：S2 作为证据和晴空增强

S2 在重庆不应成为唯一主链。建议：

- SCL 或 s2cloudless 云/云影掩膜；
- NDWI、MNDWI、AWEI；
- 多景无云合成；
- 晴空时对 S1 候选交叉验证；
- 生成审核证据图，不强行填补无数据。

输出三态：

```text
AVAILABLE_AND_SUPPORTS
AVAILABLE_AND_CONTRADICTS
UNAVAILABLE
```

不要把 `UNAVAILABLE` 当作“不变化”。

## 7. 第六优先级：对象级后处理

每个候选增加：

- area_m2；
- perimeter_m；
- compactness；
- elongation；
- stable_water_overlap；
- shoreline_distance；
- slope_mean；
- quality_score；
- persistence_count；
- sensor_support；
- exclusion_reason。

规则：

- 合并相邻碎片；
- 填充小孔；
- 简化边界；
- 排除明显桥梁、码头和坡地噪声；
- 500 m² 只作为初始阈值，按河段和任务验证；
- 保留被过滤候选和原因，便于消融。

## 8. 第七优先级：候选排序而不是只做二值输出

人工审核效率可用：

```text
priority_score =
模型置信
× 数据质量
× 时序持续性
× 稳定水体相关性
× 业务区域权重
```

其中：

- 置信度不等于严重度；
- 数据质量差时不能通过高置信掩盖；
- priority_score 只负责审核顺序；
- 比赛 PredictionRecord 不一定使用业务优先级。

重点报告 Top-20、Top-50 的有效候选比例。

## 9. 第八优先级：评测链对象化

当前 `DetectionResult` 同时服务产品和比赛，应新增：

```text
RasterObservation
WaterChangeCandidate
PredictionRecord
EvidenceAsset
```

短期通过 Adapter 映射，不立即删除旧对象。

比赛导出必须保持：

- 官方 sample_id；
- 官方顺序；
- 空预测；
- 坐标和单位；
- 数值精度；
- Schema 版本。

## 10. COG 服务修复

排查顺序：

1. `rio cogeo validate`；
2. 检查 bounds、CRS、nodata、overviews；
3. 直接访问 TiTiler info；
4. 访问 tilejson；
5. 检查 URL 前缀；
6. 浏览器 Network 中确认瓦片请求；
7. MapLibre source 使用 TileJSON 或正确 tiles URL；
8. 在 Docker/另一台机器验证，排除本地绝对路径。

验收时删除静态 PNG 兜底后页面仍能显示。

## 12. 两周执行顺序

### 第 1—2 天

- 建验证集结构；
- 标注首批样区；
- 固定 Baseline 配置；
- 输出首个指标报告。

### 第 3—4 天

- 修复 TiTiler 前缀；
- 完成真实 COG 地图；
- 加入 COG 自动校验测试。

### 第 5—7 天

- 轨道一致性、DEM 坡度和阴影质量；
- VV/VH/比值特征 A/B；
- 形成 Bad Case 分类。

### 第 8—10 天

- 多时相 median/IQR 基线；
- 持续性门禁；
- 对象级后处理和 Top-N 排序。

### 第 11—12 天

- S2 证据链；
- Candidate 与 Evidence 字段；
- DetectionResult 兼容 Adapter。

### 第 13—14 天

- Mock PredictionRecord；
- SubmissionBundle；
- 回归测试；
- Baseline Report V1。

## 13. 完成标准

遥感部分进入下一阶段必须同时满足：

- 有人工真值；
- 有总体和切片指标；
- 有可复现 Run；
- 有 Bad Case；
- 有真 COG 服务；
- 有 Candidate/Evidence；
- 有独立 PredictionRecord；
- 能明确说出哪些能力仍未验证。
