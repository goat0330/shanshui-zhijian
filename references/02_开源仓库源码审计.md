- 项目：山水智鉴
- 更新日期：2026-07-23

# 2. POS2IDON

## 2.1 仓库结构

```text
POS2IDON/
├── configs/
├── modules/
├── workflow.py
├── README.md
└── LICENSE
```

主流程涵盖：

```text
Sentinel-2 数据获取
→ 大气校正
→ 云、陆地和水体掩膜
→ 光谱指数
→ 大图切片
→ RF / XGBoost / U-Net
→ 概率或分类结果
→ 拼接和导出
```

## 2.2 值得吸收

```text
Acquisition
→ Preprocessing
→ Tiling
→ Inference
→ Mosaic
→ Product Export
```

这些阶段转换为山水智鉴自己的独立接口：

```python
class InputAdapter: ...
class Preprocessor: ...
class Tiler: ...
class ModelClient: ...
class MosaicStage: ...
class ProductWriter: ...
```

## 2.3 不继承

- Python 3.9 和旧版 PyTorch/GDAL 固定依赖；
- 约 497 行集中式 `workflow.py`；
- `import *`；
- 全局配置导入；
- 运行时自动克隆其他仓库；
- 缺少标准测试和包接口；
- GPL-3.0 核心代码。

## 2.4 决策

> 只进行干净室重构，不复制代码，不加入运行依赖。

来源：

- https://github.com/AIRCentre/POS2IDON
- https://github.com/AIRCentre/POS2IDON/blob/main/workflow.py

# 3. eoAPI、TiTiler 与 COG

## 3.1 eoAPI 的职责

```text
STAC Service
stac-fastapi + pgSTAC

Raster Service
TiTiler + pgSTAC

Vector Service
Tipg + PostGIS
```

eoAPI 解决遥感文件和模型产品的检索、瓦片和地图发布，不负责模型训练和治理事件。

## 3.2 分级采用

### V0

```text
GeoTIFF
→ rio-cogeo
→ COG
→ TiTiler
→ 地图浏览
```

### V1

```text
COG
→ STAC Item
→ pgSTAC
→ Search API
→ TiTiler
```

### V2

```text
异常图斑
→ PostGIS
→ Tipg
→ 地图和事件服务
```

### P3

完整 eoAPI 云基础设施和复杂认证。

## 3.3 决策

- `rio-cogeo`：P0 候选；
- `TiTiler`：P0 候选；
- COG：P0 输出标准；
- STAC、pgSTAC、Tipg：等待官方数据规模；
- 完整 eoAPI：当前不部署。

来源：

- https://github.com/developmentseed/eoapi-devseed
- https://github.com/developmentseed/eoapi-template

# 4. Crisis Cleanup

## 4.1 能够确认

当前公开 Web 仓库使用：

- Vue 3；
- TypeScript；
- Vite；
- Vitest；
- Playwright；
- GitHub Actions；
- Dockerfile。

项目公开说明长期服务多组织灾害协作，并具备 Case、任务、现场回传和完成状态等产品流程。

## 4.2 重要边界

当前公开组织中没有清楚确认与现行生产版本匹配的完整后端仓库。因此不能把它作为：

- 后端数据库设计来源；
- Case/WorkOrder 表结构来源；
- 权限和状态机源码来源；
- 完整前后端母仓库。

## 4.3 山水智鉴吸收内容

- 事件与任务分离；
- 一个事件拆分多个任务；
- 状态、附件和现场回传；
- 多组织协作的交互表达；
- Vitest 与 Playwright 测试组织；
- 核心闭环 E2E。

建议后续建立的首条 E2E：

```text
DetectionResult
→ 审核证据
→ 确认异常
→ 创建事件
→ 创建任务
→ 上传结果
→ 复核关闭
→ Replay
```

## 4.4 决策

> 不 Fork 整个 Vue 前端；只参考产品流程、交互和测试方法。

来源：

- https://github.com/CrisisCleanup/crisiscleanup-4-web
- https://github.com/CrisisCleanup

# 6. OpenRemote

## 6.1 有价值的抽象

```text
Asset
河段、摄像头、无人机、监测站

Agent
设备、视频流和外部 API 连接器

Attribute
位置、状态和观测值

Rule
连续异常生成告警
```

## 6.2 当前不采用

- Java、Groovy 和 TypeScript 体系较重；
- V0 没有真实设备接入；
- 已超出 IAIC 数据开放前边界；
- 设备管理不属于当前差异化核心。

## 6.3 决策

> 作为决赛后或赛后 IoT Adapter Spike 参考，当前不部署。

来源：

- https://github.com/openremote/openremote
