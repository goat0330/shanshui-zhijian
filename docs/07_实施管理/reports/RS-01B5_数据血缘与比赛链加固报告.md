## 一、B0 SarMetadataResolver 修复

### 1.1 修复前问题

| 问题 | 修复前 | 修复后 |
|------|--------|--------|
| 优先级实现 | 文档声称 A(AssetRef)→B(GeoTIFF)→C(Sidecar)→D(Inferred)，但 `resolve()` 从 B 开始，忽略 A | `_merge_asset_ref()` 在 `_read_geotiff_tags()` 前调用 |
| 来源跟踪 | 全局 `source="geotiff_tags"` 覆盖所有字段 | 每个字段单独跟踪 `_source`，逐字段合并 |
| 伪造采集时间 | `_infer()` 使用 `datetime.now().isoformat()` | 未知采集时间设为 `"UNKNOWN"`，源为 `UNKNOWN` |
| 默认平台 | `_guess_platform()` 默认 `"Sentinel-1A"` | 保留推断但明确 `source=INFERRED` |
| 默认入射角 | `incidence_angle_min=30.0`, `max=46.0` | 设 UNKNOWN 占位，strict 模式只检查关键字段 |
| strict 门禁 | 仅检查 `orbit_direction!="UNKNOWN"` 和 `relative_orbit>=0` | 检查 4 个关键字段: orbit_direction, relative_orbit, acquisition_time, polarizations |

### 1.2 MetadataSource 逐字段模型

每个字段独立跟踪来源:

```python
class SarMetadata(BaseModel):
    platform: str
    platform_source: MetadataSource  # asset_ref / geotiff_tags / sidecar / inferred / unknown
    orbit_direction: str
    orbit_direction_source: MetadataSource
    # ... 每个关键字段同理
```

### 1.3 strict/warn/trust 行为

| 模式 | orbit_direction=UNKNOWN | acquisition_time 缺失 | polarizations 不确定 |
|------|------------------------|----------------------|---------------------|
| strict | ❌ 拒绝 | ❌ 拒绝 | ❌ 拒绝 |
| warn | ⚠️ 允许, quality flag | ⚠️ 允许, quality flag | ⚠️ 允许, quality flag |
| trust | ✅ 接受 | ✅ 接受 | ✅ 接受 |

### 1.4 验证结果

36 项测试全部通过，覆盖：
- AssetRef 字段优先于 GeoTIFF
- strict 拒绝 inferred 关键字段
- warn 接受但带 quality flags
- VV 仅有 VV, VV/VH 混合
- GeoTIFF 不可读
- URI 为空

## 二、B1 Run Manifest 与运行血缘

### 2.1 Schema

```python
class RunManifest(BaseModel):
    schema_version: str = "run-manifest.v0.1-internal"
    run_id, task_id, task_spec_ref
    started_at, finished_at, duration_seconds
    status, execution_status
    git_commit, git_branch, git_dirty  # 自动捕获
    python_version, python_full, os_platform, os_release
    key_dependencies, config_hash, config_snapshot
    input_assets: list[AssetManifest]  # asset_id, uri, sha256, size_bytes
    output_artifacts: list[AssetManifest]
    error: ExecutionError | None
    manifest_sha256: str = ""  # 自身完整 SHA256
```

### 2.2 关键设计

- Git 状态使用 `subprocess.run(["git", ...])` 自动捕获
- `git_dirty=True` 时明确显示
- 非 Git 环境输出 `"unknown"`，不伪造
- 自身 `manifest_sha256` 排除自身字段计算
- `ManifestBuilder` 提供链式构建

### 2.3 验证

16 项测试全部通过，包括 `test_non_git_environment` (输出 unknown)。

## 四、B3 Mock 比赛链确定性加固

### 4.1 CompetitionInputAdapter

| 能力 | 实现 |
|------|------|
| 批量 manifest | `inference_tasks` 数组 + `inference_task` 向后兼容 |
| 稳定排序 | `tasks.sort(key=lambda t: (t.task_order, t.task_id))` |
| task_id 唯一 | `DuplicateIdError` 在 manifest 内和跨 manifest |
| sample_id 唯一 | `DuplicateIdError` |
| asset_id 唯一(Same content OK, Diff content → Error) | `DuplicateIdError` + batch 跨 manifest 内容检查 |
| 引用完整性 | `MissingAssetError` 检查 asset_binding 的引用存在 |
| task_spec_ref 非空 | `ManifestError` |
| role 合法性 | `AssetRole(role_str)` Pydantic enum 验证 |
| 空 binding | `ManifestError` |

### 4.2 CompetitionMapper

| 能力 | 实现 |
|------|------|
| task_type 分发 | `_detect_task_type()` 从 observations/diagnostics 判断 |
| 5 类型 | classification, detection, segmentation, change_detection, anomaly_scoring |
| status 语义 | no_data/failed/invalid_input → None payload |
| succeeded_empty | 对应类型的空 payload (ChangePrediction(0), DetectionPrediction([]) 等) |
| artifact 角色 | 不通过 `artifact_refs[-1]` 猜多边形文件 |
| Review 不参与映射 | PerceptionResult 到 PredictionRecord 的映射不读取 Review 数据 |

### 4.3 CompetitionExporter / SubmissionBundle

| 能力 | 实现 |
|------|------|
| 完整 SHA256 | `compute_checksum()` 返回 64 字符 hex |
| 确定性 bundle_id | 基于 `schema_version + build_version + content_hash` 的 SHA256 前缀 |
| Canonical JSON | `sort_keys=True, ensure_ascii=False, separators=(",", ":")` |
| 稳定顺序 | `sorted(predictions, key=lambda p: p.inference_task_ref)` |
| 重复 ref 拒绝 | `ValueError("重复 inference_task_ref")` |
| 元数据 | `task_count, prediction_count, source_manifest_hash, preflight_report` |

### 4.4 SubmissionValidator

| 检查项 | 实现 |
|--------|------|
| schema_version | 检查 internal 格式前缀 |
| internal_only 标记 | 明确 "当前格式为 internal mock" 警告 |
| 空 Bundle | 允许 (warning) |
| record_id 唯一 | `DuplicateIdError` |
| inference_task_ref 唯一 | `DuplicateIdError` |
| task_count 一致性 | 声明 vs 实际 |
| status-payload 一致性 | no_data/failed → payload 必须 None |
| payload 结构 | detection 空列表 warning, segmentation mask_ref 检查 |
| checksum 完整 64 位 | 长度检查 + 值匹配 |
| source_manifest_hash | 64 位长度检查 |
| 序列化可读 | `to_bytes()` 验证 |
| 顺序稳定 | `inference_task_ref` 排序检查 |

### 4.5 验证结果

40 项测试全部通过，包括:
- 同输入两次导出字节一致 ✓
- 输入顺序打乱后导出顺序一致 ✓
- 重复 task_id 失败 ✓
- 缺失 task 失败 ✓
- payload 与状态冲突失败 ✓
- checksum 被篡改失败 ✓
- 空结果合法 ✓
- NO_DATA 与 SUCCEEDED_EMPTY 语义不同 ✓
- Review 数据加入后 Bundle 不变化 ✓
- 完整 SHA256 校验有效 ✓
