## 2. 两个比赛的关系

```text
IAIC
＝验证水域异常识别、模型适配、JSON 提交和消融

智慧城市大赛
＝把已经验证的算法扩展为完整产品、实施和商业方案
```

| 维度 | IAIC | 智慧城市大赛 |
|---|---|---|
| 核心问题 | AI 能否有效识别 | 产品能否形成治理价值 |
| 主要交付 | JSON、代码、评分、消融 | 简表、说明书、商业计划、原型和答辩 |
| 共享资产 | 模型、数据、DetectionResult、评测、Bad Case | 同左，并补充业务和商业证据 |
| 差异重点 | 算法、鲁棒性、可复现 | 用户、流程、集成、应用价值和市场 |

## 3. 市场调研后的定位修正

成熟项目已经证明下列能力进入真实采购或运行：

```text
遥感或视频发现
→ 人工核验
→ 交办整改
→ 复核销号
```

因此山水智鉴不宣称首次实现人工核验、整改复核或治理闭环。

当前更可信的产品机会是：

### 3.1 模型开放接入

```text
赛事指定模型 / 自研模型 / 第三方算法
→ ModelAdapter
→ 统一 DetectionResult
```

### 3.2 证据开放组合

```text
视频 / 遥感 / 文本 / 人工核查
→ EvidenceAssembler
→ EvidenceBundle
```

### 3.3 反馈开放回流

```text
确认 / 驳回 / 处置 / 复核
→ ReplayCase
→ 治理评测 + 模型 Eval
```

## 4. 产品形态

```text
核心能力
开放治理事件中间件

操作界面
异常证据核验工作台

交付方式
API / 组件方式接入河长制、一网统管或第三方工单平台
```

山水智鉴不重复建设：

- 无人机、机巢和摄像头硬件平台；
- 完整河长制业务平台；
- 一套替代所有现有系统的城市治理大屏；
- 单一“万能”水域识别模型。

## 5. 当前范围

### 数据开放前

- 项目与赛题文档；

- Flowable、Kafka、Flink；
- 多 Agent 与大型 RAG；
- OpenRemote 和真实设备接入；
- 社会模拟、无人机自主飞行和机器人；
- 完整居民端 App。

## 6. 阶段路线

| 阶段 | 目标 | 关键交付 |
|---|---|---|
| 调研收束 | 明确市场已有能力与源码边界 | 十个市场案例、五个源码对象审计 |
| 实现前 Spike | 验证自研边界可以跑通 | Pipeline、TiTiler、人工核验 |
| 官方数据接入 | 快速形成首个可提交结果 | 数据审计、Adapter、JSON、评分 |
| 算法优化 | 建立可解释的分数提升 | Slice、Bad Case、消融 |
| 产品化 | 形成完整 Vertical Slice | Event、WorkOrder、Replay、E2E |
| 双赛交付 | 分别满足算法赛和产品赛 | 两套材料和同一证据库 |

## 7. 核心架构原则

1. 算法链和产品链硬隔离；
2. 模型结果不直接成为治理事件；
3. 公开材料未说明不等于市场不存在；
4. 宽松许可组件可直接依赖，GPL/AGPL 项目只借鉴思想；
5. 所有实验数字有唯一事实源；
6. 技术只有通过 Spike 才进入正式依赖；
7. 既有治理平台是集成对象，不是替代对象。

## 8. 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 官方任务形式未知 | 代理方案需要调整 | 接口先行，不冻结最终模型 |
| 基座模型和调用限制未知 | 提交链阻塞 | 统一 ModelClient |
| 市场差异化被反证 | 竞赛叙事失真 | 以标准化和可评测为核心 |
| 过度工程化 | 延误初赛 | 三个 Spike 作为前置 Gate |
| 两赛内容相似 | 合规和评审风险 | 共享技术资产，区分问题与验收 |
