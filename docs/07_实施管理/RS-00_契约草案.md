## 1. 对象职责与关系图

### 1.1 顶层关系

```
CompetitionInput / Fixture
        │
        ▼
CompetitionInputAdapter
        │
        ├── 注册或构建 AssetRef
        └── 生成 InferenceTask[]
                    │
                    ├── task_spec_ref ────────► TaskSpec
                    └── asset_refs ───────────► AssetRef[]
                    │
                    ▼
             PerceptionTool
              (InferenceTask + TaskSpec + RunContext)
                    │
                    ▼
             PerceptionResult
              ├── Observation[]
              ├── artifact_refs[]
              ├── quality_report
              └── diagnostics
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
     ProductMapper       CompetitionMapper
          │                   │
          ▼                   ▼
  DetectionCandidate     PredictionRecord
  EvidenceRef                  │
  AnomalyEvent                ▼
                       CompetitionExporter
                              │
                              ▼
                       SubmissionBundle
```

### 1.2 核心分离规则

| 层 | 对象 | 描述"什么" | 不描述什么 |
|----|------|-----------|-----------|
| 规则定义 | `TaskSpec` | 一类任务需要的 InputSlot 和产出契约 | 不携带具体资产，不携带算法参数 |
| 执行配置 | `RunContext` / `ToolConfig` | 工具阈值、窗口大小、模型版本 | 不描述任务规则 |
| 样本上下文 | `InferenceTask` | 具体样本 ID、顺序、资产绑定 | 不携带任务规则定义 |
| 工具输出 | `PerceptionResult` | 工具运行后的事实层结果 | 不携带比赛或产品业务状态 |
| 产品链 | `Observation → DetectionCandidate → AnomalyEvent` | 观测、候选、事件 | 不生成比赛提交 |
| 比赛链 | `PredictionRecord → SubmissionBundle` | 官方投影、提交包 | 不依赖产品链的事件状态 |
| 输入绑定 | `TaskAssetBinding` | 将 AssetRef 与语义角色绑定 | 不独立存在，必须属于 InferenceTask |

## 2. 对象定义

### 2.1 AssetRef

输入资产的轻量引用，不是完整 `Asset`。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `asset_id` | string | 是 | 资产稳定 ID |
| `uri` | string | 是 | 文件路径或 URL |
| `media_type` | string | 是 | `image/tiff; application=geotiff` / `image/png` / 等 |
| `modality` | string | 是 | `sar` / `optical` / `dem` / `vector` / `mask` / `video` / `metadata` / `unknown` |
| `spatial` | dict | 否 | 见 2.3 |
| `bands` | string[] | 否 | `["B2","B3","B4","B8"]` |
| `acquisition_time` | string | 否 | RFC 3339 |
| `checksum` | string | 否 | SHA-256 |

### 2.2 TaskAssetBinding

将资产引用与任务中的语义角色绑定在一起。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `asset_ref` | string | 是 | 引用 AssetRef 的 asset_id |
| `role` | string | 是 | 该资产在任务中的语义角色，见下方 |
| `sequence_index` | int | 否 | 同角色的顺序索引（多时相标记 t0/t1/t2） |

**role 取值**：

| 值 | 含义 | 示例 |
|------|------|------|
| `before` | 对比/变化检测的前期 | S1 T1, S2 T1 |
| `after` | 对比/变化检测的后期 | S1 T2, S2 T2 |
| `history` | 历史数据（多时相中的早期期次） | 第 3 期及之后的时序 |
| `current` | 当前监测期 | 实时/最近采集 |
| `auxiliary` | 辅助/背景数据 | DEM, WorldCover |
| `prior` | 先验数据 | JRC 稳定水体 |
| `mask` | 掩膜数据 | cloud mask, water mask |
| `label` | 标签/标注数据 | 验证集 GeoJSON |
| `spatial_metadata` | 空间元数据（CRS/仿射/尺寸） | PNG 配准文件 |
| `optical_support` | 光学辅助证据 | S2 晴空影像 |

### 2.3 spatial 结构

```yaml
spatial:
  reliability: georeferenced | pixel_only | approximate | unknown
  crs: EPSG:4545
  transform: [a, b, c, d, e, f]
  bounds: [xmin, ymin, xmax, ymax]
  width: 512
  height: 512
```

`reliability` 的语义：

| 值 | 含义 | 可执行的操作 |
|------|------|-----------|
| `georeferenced` | 有 CRS 和 transform | 精确面积、位置叠加 |
| `pixel_only` | 只有像素尺寸，无地理定位 | 不能计算面积，不能叠加地图 |
| `approximate` | 有粗略地理参考（如相机位姿估算） | 可推断方向，不可精确测量 |
| `unknown` | 空间信息缺失 | 无法做任何空间结论 |

### 2.3 TaskSpec

描述一类任务的规则。**不携带具体资产**，**不携带工具参数**。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `task_spec_id` | string | 是 | 规则 ID，如 `sar-temporal-change-v1` |
| `version` | string | 是 | 语义版本 |
| `task_type` | string | 是 | `temporal_change_detection` / `water_extraction` / `object_detection` / `classification` |
| `task_fingerprint` | string | 是 | 任务规则指纹（task_spec_id + version 的哈希）|
| `input_slots` | InputSlotSpec[] | 是 | 输入槽位定义，描述每个 role 的模态约束 |
| `output_contract` | dict | 是 | 输出类型定义，见下方 |
| `validation_policy` | dict | 否 | 验证策略引用 |

**output_contract 示例**：

```yaml
output_contract:
  prediction_type: change_detection
  outputs:
    - change_mask
    - change_polygons
  geometry_types:
    - polygon
    - multi_polygon
```

### 2.4 InputSlotSpec

描述一个输入槽位的约束。TaskSpec 通过 input_slots 声明需要哪些 role、每种 role 允许的 modalitiy 和数量范围。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `role` | string | 是 | 语义角色，与 TaskAssetBinding.role 对应 |
| `modalities` | string[] | 是 | 允许的 modality，如 `["sar"]` 或 `["sar", "optical"]` |
| `min_items` | int | 是 | 最少需要此 role 的资产数（通常是 1）|
| `max_items` | int | 是 | 最多允许此 role 的资产数（0 表示不限）|

```yaml
# 示例：SAR 双时相变化检测的槽位
- role: before
  modalities: [sar]
  min_items: 1
  max_items: 1
- role: after
  modalities: [sar]
  min_items: 1
  max_items: 1
- role: optical_support
  modalities: [optical]
  min_items: 0
  max_items: 3
```

### 2.5 InferenceTask

比赛评测链的输入单元，**携带具体样本上下文和资产引用**。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `task_id` | string | 是 | 系统内任务 ID |
| `sample_id` | string | 是 | 样本标识（可能等于官方 ID） |
| `task_order` | int | 是 | 内部顺序，从 **0 开始**；提交时由 Exporter 映射 |
| `task_spec_ref` | string | 是 | 引用 TaskSpec，如 `sar-temporal-change-v1@1.0.0` |
| `asset_bindings` | TaskAssetBinding[] | 是 | 本样本的具体资产绑定 |
| `idempotency_key` | string | 否 | 幂等键 |

**与 V0.1 的关键区别**：
- 不再嵌套 `task_spec` 对象，改为 `task_spec_ref` 字符串引用
- `asset_refs` 替换为 `asset_bindings`，每个绑定携带 role
- `task_order` 内部从 **0 开始**，提交时由 Exporter 映射
- 一条 InferenceTask 对应一条 PredictionRecord（1:1）
- 删除了 `rule_version`（移入 TaskSpec.validation_policy）

### 2.6 PerceptionTool 接口

```
class PerceptionTool(Protocol):
    def run(
        self,
        task: InferenceTask,
        spec: TaskSpec,
        context: RunContext,
    ) -> PerceptionResult:
        ...
```

**三个输入参数的分工**：

| 参数 | 提供 | 示例 |
|------|------|------|
| `task` (InferenceTask) | 具体样本和资产 | 当前样本的 S1 T1/T2 路径 |
| `spec` (TaskSpec) | 任务规则 | 需要 before/after 角色、SAR 模态 |
| `context` (RunContext) | 运行配置 | 工具阈值、模型版本、输出目录、运行 ID |

### 2.7 RunContext

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `run_id` | string | 是 | 运行 ID |
| `run_fingerprint` | string | 是 | 运行指纹（tool_config + model_version + input asset hashes 的哈希）|
| `tool_config` | dict | 否 | 工具参数，如 `{"otsu_grid": 50, "min_area_m2": 500, "speckle_filter": true}` |
| `model_version` | string | 否 | 模型/规则版本 |
| `output_dir` | string | 否 | 产物输出目录 |

### 2.8 PerceptionResult

感知工具的唯一返回对象。产品链和比赛链都从这里分叉。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `schema_version` | string | 是 | `rs-contract.v0.2` |
| `perception_result_id` | string | 是 | 结果唯一 ID |
| `inference_task_ref` | string | 是 | 关联的 InferenceTask ID |
| `task_spec_ref` | string | 是 | 关联的 TaskSpec 引用 |
| `run_id` | string | 是 | 运行 ID |
| `status` | string | 是 | 执行状态，见第 4 节 |
| `observations` | Observation[] | 否 | 结构化观测列表 |
| `artifact_refs` | string[] | 否 | 派生 Asset ID（掩膜/栅格/GeoJSON），非 Evidence |
| `quality_report` | dict | 否 | 质量报告，见 2.9 |
| `diagnostics` | dict | 否 | 诊断信息 |
| `started_at` | string | 否 | RFC 3339 |
| `finished_at` | string | 否 | RFC 3339 |

**artifact_refs 与 EvidenceRef 的区别**：
- `artifact_refs` 是工具产出的**派生产物 Asset ID**（整体变化掩膜、分数栅格、合并 GeoJSON），直接从 PerceptionTool 返回
- `EvidenceRef` 是产品研判阶段从 artifact 中**选用的证据片段**（裁剪后的局部切片、叠加图），由 ProductMapper 在形成 DetectionCandidate 时创建### 2.9 quality_report

```yaml
quality_report:
  valid_pixel_ratio: 0.85
  cloud_ratio: 0.05
  registration_quality: 0.9
  sensor_comparability: true
  reasons:
    - low_cloud
    - same_orbit_pair
```

`no_data` 时：

```yaml
quality_report:
  valid_pixel_ratio: 0.03
  cloud_ratio: 0.92
  reasons:
    - excessive_cloud
```

### 2.10 Observation

单次结构化观测。产品链从这里开始。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `schema_version` | string | 是 | `rs-contract.v0.2` |
| `observation_id` | string | 是 | 观测 ID |
| `perception_result_ref` | string | 是 | 关联的 PerceptionResult ID |
| `source_asset_refs` | string[] | 是 | 来源资产 ID 列表 |
| `source_task_type` | string | 是 | 任务类型，继承自 TaskSpec |
| `observation_type` | string | 是 | 观测事实类型，见下方 |
| `label` | string | 是 | 观测标签 |
| `score` | float | 是 | 分数（0-1） |
| `score_type` | string | 是 | `model_probability` / `rule_based` / `ensemble` |
| `geometry` | GeoJSON | 否 | 空间位置 |
| `bbox` | float[] | 否 | `[xmin, ymin, xmax, ymax]` |
| `temporal` | dict | 否 | `{"start": "...", "end": "..."}` |
| `quality` | dict | 否 | 质量标记 |
| `model_run_ref` | string | 否 | 模型运行引用 |
| `coordinate_space` | string | 否 | `geographic` / `pixel` / `unknown` |
| `created_at` | string | 否 | RFC 3339 |

**observation_type 取值**：

| 值 | 含义 |
|------|------|
| `sar_backscatter_change` | SAR 后向散射变化 |
| `optical_water_index` | 光学水体指数观测 |
| `optical_water_index_support` | 光学水体指数辅助证据 |
| `water_extent` | 水体范围提取 |
| `change_polygon` | 变化图斑 |
| `object_detection` | 目标检测结果 |
| `anomaly_score` | 异常分数 |

**与 V0.1 的关键区别**：
- `task_type` 拆分为 `source_task_type` + `observation_type`
- 增加 `perception_result_ref` 和 `source_asset_refs`，实现全链路追溯
- 增加 `coordinate_space`（区分地理坐标和像素坐标）
- 增加 `created_at`

| 字段 | 类型 | 必需 | 说明 |

### 2.13 PredictionRecord

比赛评测链：从 PerceptionResult 投影到官方格式的记录。

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `schema_version` | string | 是 | `rs-contract.v0.2` |
| `record_id` | string | 是 | 记录 ID |
| `inference_task_ref` | string | 是 | 关联 InferenceTask ID（1:1）|
| `perception_result_ref` | string | 是 | 关联 PerceptionResult ID |
| `execution_status` | string | 是 | 继承自 PerceptionResult.status |
| `prediction_type` | string | 是 | `change_detection` / `classification` / `detection` / `segmentation` / `anomaly_scoring` |
| `payload` | PredictionPayload | 是 | **内部判别联合**，见 2.14 |
| `model_run_ref` | string | 否 | 模型运行引用 |

**与 V0.1 的关键区别**：
- `status` 改为 `execution_status`，与 PerceptionResult 保持一致
- 增加 `prediction_type` 作为判别字段
- `payload` 不再是裸 dict，而是判别联合类型
- 裸 dict 只允许出现在 `CompetitionExporter` 的输出边界

### 2.14 PredictionPayload 判别联合

```python
Annotated[
    ClassificationPrediction
    | DetectionPrediction
    | SegmentationPrediction
    | ChangePrediction
    | AnomalyScorePrediction,
    Field(discriminator="prediction_type"),
]
```

每种类型的结构：

```yaml
# ClassificationPrediction
prediction_type: classification
class_id: 3
class_name: water
confidence: 0.92

# DetectionPrediction
prediction_type: detection
detections:
  - bbox: [100, 200, 150, 250]
    class_id: 1
    confidence: 0.85

# SegmentationPrediction
prediction_type: segmentation
mask_ref: asset-water-mask
class_map: {0: "background", 1: "water", 2: "vegetation"}

# ChangePrediction
prediction_type: change_detection
change_mask_ref: asset-change-mask
polygons_ref: asset-change-polygons
change_pixels: 5084

# AnomalyScorePrediction
prediction_type: anomaly_scoring
score_map_ref: asset-anomaly-scores
mean_score: 0.65
threshold: 0.70
```

## 3. 五类执行状态

| 状态 | 含义 | 产物链行为 | 内部比赛链行为 | 导出行为（由 Policy 决定） |
|------|------|-----------|-------------|------------------------|
| `succeeded_with_observations` | 数据有效、工具成功、产出 >= 1 个 Observation | → DetectionCandidate(s) | → PredictionRecord(payload 非空) | 正常导出 |
| `succeeded_empty` | 数据有效、工具成功、产出 0 个 Observation | → 不生成 Candidate | → PredictionRecord(status=succeeded_empty) | 导出空结果 |
| `no_data` | 数据不足（云/无效像元/缺波段）| → 不生成 Candidate | → PredictionRecord(status=no_data) | 导出"无法判断"或跳过 |
| `invalid_input` | 输入格式/CRS/角色不符合 | → 不生成，报错 | → PredictionRecord(status=invalid_input) | 阻止 Bundle 或标记失败 |
| `failed` | 工具内部错误 | → 不生成，报错 | → PredictionRecord(status=failed) | 阻止 Bundle 或重试 |

### 关键规则

| 规则 | 说明 |
|------|------|
| `succeeded_empty` ≠ `no_data` | 前者"数据好没发现"，后者"数据不好没法判断" |
| `invalid_input` ≠ `failed` | 前者调用方修复，后者工具方修复 |
| `no_data` 不生成虚假 Observation | `observations: []`，质量原因写入 `quality_report` |
| 各状态在内部全程保持独立 | 不把 `invalid_input` 折叠为 `failed`，导出行为由 `CompetitionProfile/ExportPolicy` 决定 |

## 5. DetectionResult 兼容映射

### 5.1 总原则

DetectionResult 通过 **DetectionResultAdapter** 转换为新对象，不修改现有代码。

### 5.2 映射表

| DetectionResult 字段 | 产品链映射 | 比赛链映射 |
|----------------------|-----------|-----------|
| `detection_id` | `Observation.observation_id` | — |
| `task_type` | `Observation.source_task_type` | — |
| `category` | `Observation.label` | `PredictionRecord.payload` 中的类别 |
| `geometry` | `Observation.geometry` | `PredictionRecord.payload` 中的几何 |
| `confidence` | `Observation.score` | — |
| `score_type` | `Observation.score_type` | — |
| `model.name/version` | → 先构建 `RunContext.model_version`，再引用 | 同左 |
| `source_assets` | `Observation.source_asset_refs` | `InferenceTask.asset_bindings`（由 Adapter 构建） |
| `observed_at` | `Observation.temporal` | — |
| `properties` | `Observation` 扩展字段 | — |

### 5.3 DetectionResultAdapter 接口

```python
class DetectionResultAdapter:
    @staticmethod
    def to_perception_result(
        dr_list: list[dict],
        inference_task: InferenceTask,
        context: RunContext,
    ) -> PerceptionResult:
        """将一组 DetectionResult 聚合为一个 PerceptionResult"""
    
    @staticmethod
    def to_observations(dr_list: list[dict]) -> list[Observation]:
        """DetectionResult 列表 → Observation 列表"""
    
    @staticmethod
    def to_prediction_record(
        dr_list: list[dict],
        inference_task: InferenceTask,
        perception_result: PerceptionResult,
    ) -> PredictionRecord:
        """整个 InferenceTask 对应一个 PredictionRecord"""
```

**与 V0.1 的关键区别**：
- `to_prediction_record` 接收的是整个 InferenceTask 的 DetectionResult 列表，生成一条 PredictionRecord
- `model.name/version` 先构建 `RunContext`，再通过 `model_run_ref` 引用
- `source_assets` 映射到 `Observation.source_asset_refs`，不是直接变成证据

## 附录 A：术语对照表

| 术语 | 含义 |
|------|------|
| AssetRef | 输入资产的轻量引用，不含完整血缘/许可信息 |
| TaskSpec | 任务规则定义，描述一类任务的输入角色、模态和产出契约 |
| InferenceTask | 比赛评测链的具体样本上下文，携带资产引用 |
| RunContext | 工具运行时的配置、版本和输出目录 |
| PerceptionTool | 感知工具接口，可替换 |
| PerceptionResult | 工具运行的唯一返回对象 |
| Observation | 单次结构化观测事实 |
| DetectionCandidate | 产品链中的算法候选 |
| EvidenceRef | 证据引用，指向源资产或派生资产 |
| PredictionRecord | 比赛评测链中的预测记录 |
| CompetitionExporter | 将 PredictionRecord 映射为官方格式导出 |
| SubmissionBundle | 不可变的比赛提交包 |
