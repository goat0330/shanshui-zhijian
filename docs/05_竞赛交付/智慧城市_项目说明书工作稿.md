# 一、立项依据｜不超过 2000 字

## 1. 行业问题

成熟水域治理项目已经覆盖无人机巡河、高点视频、遥感发现、人工核验、整改复核和销号。政府实际采购的交付物包括问题图斑、核查报告、自动预警、设备平台升级和年度巡检运营。

新的集成难题是：

- 多种模型和厂商输出如何统一；
- 多帧、多时相和多来源结果如何形成同一证据；
- 人工确认和驳回如何留痕；
- 处置与复核结果如何形成模型 Eval；
- 替换模型时是否需要重新开发业务平台。

## 2. 市场现状

十个真实项目和第二轮采购补证见 `references/01_市场与采购项目审计.md`。

市场已经存在五类交付：

1. 算法＋人工服务；
2. 高点视频识别服务；
3. 遥感＋无人机核查；
4. 设备＋平台升级；
5. 巡检运营服务。

## 3. 项目问题定义

山水智鉴不替代现有河长制和城市治理平台，而是解决模型、证据和反馈数据之间的标准化断点。

# 二、项目创新内容｜不超过 3000 字

## 1. 总体思路

```text
任意感知模型
→ 标准 DetectionResult
→ EvidenceBundle
→ AnomalyAlert
→ 人工核验
→ 既有治理流程
→ Replay / Eval
```

## 2. 可行性

- IAIC 提供官方数据和统一评测；
- Python、Pydantic、Rasterio、COG 和 TiTiler 有成熟组件；
- 产品链可先使用 Mock 数据完成最小 Vertical Slice；
- 项目不承担硬件平台和完整政务系统替换；
- 核心接口和业务对象可通过单元与 E2E 测试验证。

## 3. 特色与创新

### 开放模型接入

赛事模型、自研视频/遥感模型和第三方算法使用统一 Adapter。

### 多源证据编排

连续帧、遥感图斑、文本和人工核查形成 EvidenceBundle。

### 识别与治理解耦

模型结果不会直接生成正式治理事件，必须经过规则和人工核验。

### 双重 Replay 与 Eval

同一反馈同时支持治理过程评价和模型错误分析。

### 面向既有平台的组件化集成

通过标准 API 输出事件和证据，不要求客户更换原业务平台。

# 三、实施方案｜不超过 3000 字

## 1. 算法链

```text
DatasetAdapter
→ ModelClient
→ OutputParser
→ PostProcessor
→ Evaluation
→ JSON
```

## 2. 遥感 Pipeline

```text
InputAdapter
→ Preprocessor
→ Tiler
→ Inference
→ Mosaic
→ ProductWriter
```

V0 使用 COG + TiTiler；STAC、pgSTAC 和 Tipg 根据数据规模后置。

## 3. 产品链

```text
DetectionResult
→ EvidenceBundle
→ AnomalyAlert
→ Review
→ GovernanceEvent
→ ResponsibilityRouter
→ WorkOrder
→ ReplayCase
```

数据开放前先做到人工确认或驳回；首个稳定 Baseline 后补完整工单闭环。

## 4. 实验

## 5. 实施阶段

6. 后续试点和平台集成。

# 四、应用前景分析｜不超过 500 字

山水智鉴可作为既有河长制、一网统管、生态环境或水库运营平台的 AI 能力模块，也可向系统集成商和算法厂商提供标准化模型接入、证据核验和反馈评测服务。初期聚焦高点视频和遥感水域异常，后续可扩展水葫芦、蓝藻、岸线破坏、排污溯源等专项模型。商业交付可采用私有部署、API 集成、专项巡检与年度模型运维。项目当前处于竞赛与原型验证阶段，实际经济效益需在官方数据实验、专家评审和试点后评估。
