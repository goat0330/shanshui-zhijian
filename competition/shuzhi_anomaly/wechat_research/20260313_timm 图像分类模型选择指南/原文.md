# timm 图像分类模型选择指南

> 虽然大语言模型和多模态模型占据了大量关注，但在纯视觉任务，如图像分类、特征提取中，选择一个合适的 Backbone 依然是工程落地的核心。**PyTorch Image Models (也就是timm)** 依然是计算机视觉领域，特别是图像分类的常用的模型库。
> 如何从 timm 提供的上千个模型中做出最优选择，还是需要根据具体数据量和部署环境来考虑。

## 核心概念：归纳偏置

在讨论模型之前，必须先理解归纳偏置。它指的是模型在面对未见过的数据时，对解空间所做的假设。

- • **CNN**：即卷积神经网络。它假设图像具有**平移不变性**，即一只猫在左上角和右下角都是猫；以及**局部性**，即像素点和周围的像素点关系更密切。
这种假设非常符合自然图像的规律，因此CNN在小数据上也能学得很好，因为它自带了先验知识。但是也限制了模型的上限，难以捕捉长距离的全局依赖。
- • **ViT**：即视觉Transformer。它从来不假设图像块之间存在某种关联，通过 **Self-Attention** 机制去学习这种关联。它几乎没有先验假设。只要数据量足够大，它能学到比CNN更复杂的特征，上限极高。但是如果数据量不够时，它也不容易学习好。

## 场景一：基于数据集大小的选择

### 1. 小数据集

**定义**：每个类别样本数少于1000，或者总数据量少于10万张。

在这种场景下，我们需要依赖**强归纳偏置**的模型，或者依赖**迁移学习**。

- • EfficientNetV2 或 MobileNetV4

- • 这两者都是经过**神经架构搜索**优化的 CNN。
- • **EfficientNetV2** 在训练速度和参数效率上达到了极佳的平衡，引入了 Fused-MBConv 结构，比 V1 快得多。
- • **MobileNetV4** 是移动端王者，但在服务器端做小任务也极快，且极难过拟合。

- • ConvNeXt Tiny 或 Small

- • **ConvNeXt** 是现代化的 CNN。它借鉴了 Transformer 的设计思路，如 Patchify Stem 和 Depthwise Conv 模拟 MSA，以及更大的 Kernel size，但保留了卷积的归纳偏置。

### 2. 大数据集

**定义**：ImageNet-1k 级别，即128万张图片或更大；或者你有数亿张无标注图片做自监督预训练。

数据量不再是瓶颈，模型的**容量**才是。

- • **首选：Vision Transformer (ViT)**

- • 虽然是2020年的架构，但在2026年，**ViT** 依然是扩展性最好的架构。
- • 配合 **MAE** 即掩码自编码器，或 **CLIP** 以及 **SIGLIP** 预训练权重，ViT-Large 或 Huge 是刷榜神器。

- • **Swin Transformer V2**

- • 解决了标准 ViT 在高分辨率图像上计算量呈平方级增长的问题。
- • **窗口注意力**机制引入了局部性，使得它在密集预测任务如检测、分割上表现通常优于标准 ViT。

- • **MaxViT**

- • Google 推出的结合了 CNN 和 Transformer 的模型。
- • 利用 **MBConv** 做局部特征，**Block Attention** 做全局特征。
- • *缺点*：结构复杂，推理延迟可能较高，不如纯 ViT 部署方便。

## 场景二：基于部署硬件的选择

### 1. 端侧、移动端或物联网设备

**目标**：低延迟，低功耗，小模型体积。

- • **MobileNetV4**

- • 这是 Google 在2024年推出的力作，针对移动端 NPU 和 CPU 进行了极致优化。
- • 它引入了 **UIB** 模块，搜索出的架构在手机上性能非常好。

- • **慎用 ViT**

- • 虽然有 **MobileViT**, **EdgeViT** 等轻量级 Transformer，但在很多端侧 NPU 上，**Reshape** 和 **Softmax** 操作依然是性能瓶颈。
- • 理论 FLOPs 低不代表推理速度快。在树莓派或手机 DSP 上，纯卷积的 **MobileNetV4** 或 **EfficientNet-Lite** 往往比同 FLOPs 的 Transformer 快一倍以上。

- • **FastViT 或 EdgeNeXt**

- • 如果确实需要 Transformer 的精度，可以选择这些专门为端侧优化的混合模型，它们用**重参数化技术**在推理时合并分支，提升速度。

### 2. 云端或高性能GPU

**目标**：高吞吐量，显存利用率。

- • **首选：ViT Base, Large 或 Huge**

- • GPU 最喜欢并行的矩阵乘法。ViT 的结构极其规整，非常适合 GPU 并行加速。
- • 配合 **FlashAttention** 技术，ViT 的推理速度非常快。

- • **替代：ConvNeXt**

- • 在相同 FLOPs 下，ConvNeXt 在 GPU 上的吞吐量通常略低于 ViT，因为 Depthwise Conv 在 GPU 上不如 Dense Matrix Multiplication 高效，但差距已经很小。
- • 如果你需要处理非常大的分辨率，如 4K 医疗影像，ConvNeXt 的全卷积结构比 ViT 更节省显存。

## 预训练权重优于模型架构

timm 提供了大量来自不同源的预训练权重。在选择模型时，不要只看 model_name，更要看 pretrained_cfg。

- 1. **ImageNet-1k Pretrained**：标准配置，适合通用任务。
- 2. **ImageNet-21k 或 22k**：包含更细粒度的类别。如果你的下游任务比较生僻，如某种特定植物分类，加载 21k 的权重微调效果会显著好于 1k。
- 3. **CLIP, SIGLIP 或 DINOv2**：
这些模型在大规模图文对或无标签数据上训练。它们学到的特征具有极强的**鲁棒性**和**语义理解能力**。
*建议*：优先尝试 vit_base_patch16_siglip_224 或 vit_large_patch14_dinov2，即使做简单的分类任务，它们的少样本能力也远超传统监督学习训练的 ResNet。
