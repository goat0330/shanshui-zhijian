# 03 — 技术架构与开源底座

> 本文件给出架构摘要和实施边界。完整设计见 `docs/06_架构设计/`。

## 1. 当前实现与目标架构

当前实现：

```text
GEE/GeoTIFF
→ 遥感 Pipeline
→ DetectionResult
→ FastAPI
→ SQLite
→ Jinja2 + MapLibre
```

目标架构：

```text
L8 体验层
L7 应用服务层
L6 事件智能层
L5 感知工具层
L4 数据处理层
L3 数据与证据层
L2 接入适配层
L1 运行保障层
```

迁移采用兼容适配器，不进行一次性重写。

## 2. 两条独立链

### 产品治理链

```text
Asset
→ Observation
→ DetectionCandidate
→ AnomalyEvent
→ ReviewDecision
→ AlertDelivery
→ IncidentCase
```

### 比赛评测链

```text
CompetitionInput
→ InferenceTask
→ PredictionRecord
→ SubmissionBundle
→ SubmissionAttempt
```

`DetectionResult` 保留为 V0 兼容对象，由适配器分别映射到 Candidate 或 PredictionRecord。

## 4. 模块化单体

当前阶段采用：

```text
一个仓库
一个 FastAPI 应用
一个领域数据库
多个可独立运行的 Worker
清晰模块边界
```

不提前拆微服务，因为团队规模、官方任务、视频数量和部署环境仍不确定。

建议后端模块：

```text
sources
assets
observations
candidates
events
reviews
evidence
alerts
runs
submissions
```

## 5. 数据存储

| 数据 | V0 | 目标 |
|---|---|---|
| 元数据与状态 | SQLite | PostgreSQL/PostGIS |
| 原始和派生大文件 | 文件目录 | 对象存储抽象 |
| COG | 本地文件 | 对象存储 + 签名 URL |
| 运行日志 | 结构化文件/日志 | 可观测性平台 |
| 官方提交 | 独立目录 | 版本化 Submission Store |

原始资产不可覆盖。派生资产必须记录上游资产、处理版本和配置。

## 6. 一致性与可靠性

逐步加入：

- 幂等键；
- 乐观锁；
- 任务租约和心跳；
- 重试次数；
- inbox/outbox；
- 追加式审计；
- Event 版本；
- 数据库迁移；
- 失败和无数据的独立语义。

不以“页面能够操作一次”代替一致性验收。

## 7. 遥感 Pipeline

```text
InputAdapter
→ Preprocessor
→ FeatureExtractor
→ ModelOrRuleClient
→ ChangeDetector
→ Fusion
→ Polygonizer
→ ProductWriter
```

每层要求：

- 配置显式；
- 无全局变量；
- 输入输出可测试；
- 中间产物可检查；
- 运行可复现；
- 不绑定某个官方格式或前端对象。

## 8. 高点视频

首轮只做：

```text
授权 MP4
→ 解码/时间轴
→ 2 FPS 抽帧
→ 质量检查
→ 水面 ROI
→ 简单基线或 Mock
→ Observation
→ Candidate
→ 关键帧 Evidence
→ Review
```

不先做多路 RTSP、复杂 PTZ、WebRTC、完整边缘集群或自动工单。
