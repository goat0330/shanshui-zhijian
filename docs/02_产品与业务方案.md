# 02 — 产品与业务方案

> 说明产品用户、业务对象、人机边界、页面和 MVP。产品治理链不得代替比赛评测链。

## 1. 用户

| 用户 | 主要任务 |
|---|---|
| 研判人员 | 查看候选与证据，确认、驳回或标记不确定 |
| 管理人员 | 查看事件分布、来源健康、审核积压和处置状态 |
| 算法人员 | 查看 Run、质量、Bad Case 和反馈切片 |
| 平台集成人员 | 通过 API 接入既有河长制、一网统管或工单系统 |
| 比赛团队 | 独立运行评测链和生成 SubmissionBundle |

## 2. 核心对象

| 对象 | 含义 | 谁产生 |
|---|---|---|
| Source | 数据来源或设备 | 配置/平台 |
| Asset | 原始或派生资产 | Adapter/处理链 |
| Observation | 模型或工具观察到的事实 | 感知工具 |
| DetectionCandidate | 基于观测提出的待研判假设 | 规则/模型 |
| Evidence | 支持判断的图像、视频、栅格、矢量或文本 | 系统 |
| AnomalyEvent | 聚合后进入业务研判的事件 | 事件智能层 |
| ReviewDecision | 人工判断记录 | 研判人员 |
| AlertDelivery | 消息发送尝试与结果 | 通知服务 |
| IncidentCase | 确认后进入处置的案件 | 产品或外部平台 |
| PredictionRecord | 比赛样本预测 | 评测链 |
| SubmissionBundle | 官方提交包 | 评测链 |

## 3. 人机边界

机器可以：

- 读取资产；
- 执行质量检查；
- 生成 Observation；
- 提出 Candidate；
- 聚合相似候选；
- 生成证据；
- 推荐优先级；
- 形成 PredictionRecord。

机器不能自动声称：

- 变化等于污染；
- 候选等于政府认定异常；
- 高置信等于高严重度；
- 告警发送成功等于处置完成；
- 比赛预测经过人工审核后更“合法”。

人工负责：

- 确认、驳回、不确定；
- 记录原因；
- 调整事件聚合；
- 判断是否进入 IncidentCase；
- 对外部治理后果负责。

## 4. 最小产品链

```text
Asset
→ Observation
→ Candidate
→ Evidence
→ Event
→ Review
```

P0 到此为止。现有 WorkOrder 页面作为演示资产保留，但不继续扩大为完整工单中心。

正式处置优先采用：

```text
IncidentCase
→ API
→ 既有治理或工单平台
```

## 5. 产品页面

### 5.1 态势总览

- 地图；
- 数据来源和最近运行；
- 候选与事件统计；
- 质量异常；
- 图层透明度和时间切换。

### 5.2 异常研判

- 候选队列；
- 原始影像、预测、时序和质量证据；
- 确认、驳回、不确定；
- 结构化原因；
- 上一条/下一条和快捷操作。

### 5.3 事件详情

- Observation 和 Candidate 关系；
- Evidence 时间线；
- Review 历史；
- Event 合并与拆分；
- 外部处置引用。

### 5.4 来源与运行

- 视频、遥感和模型来源；
- Run 状态；
- 失败、重试、积压和数据质量；
- 配置、代码和模型版本。

### 5.5 评测实验室

- 数据版本；
- 模型运行；
- PredictionRecord；
- SubmissionBundle；
- Schema 校验；
- 指标、切片与 Bad Case。

评测实验室只展示评测链，不读取产品 Review 结果生成提交。

## 6. 状态设计

以下状态必须分开：

- 生命周期：new / under_review / confirmed / rejected / closed；
- 数据质量：valid / degraded / no_data / invalid；
- 运行错误：pending / running / failed / retrying / succeeded；
- 告警发送：queued / sent / delivered / failed；
- 严重度：业务影响；
- 置信度：模型可信程度。

一个对象可以“运行成功但数据质量差”，也可以“模型高置信但业务严重度低”。

## 7. 当前 MVP

包含：

- 遥感资产和候选；
- 地图；
- 人工核验；
- SQLite 持久化；
- Event/Replay 演示；
- API 文档；
- 评测链骨架。

不包含：

- 完整权限体系；
- 多租户；
- 完整工单和绩效；
- 多路实时视频；
- 生产级消息系统；
- 自动执法或自动销号。

## 8. 产品验收

MVP 不是“页面很多”，而是：

1. 任一 Candidate 能追溯到 Asset、Run 和配置；
2. 研判人员能看见足够证据；
3. Review 不覆盖原始模型输出；
4. Event 聚合过程可解释；
5. 产品链和比赛链互不污染；
6. 服务重启不丢记录；
7. 失败和无数据可以被区分。
