# 03 — 技术架构与开源底座

> 记录技术选型、模块边界和开源仓库审计。只保留三类：直接使用、技术验证、暂不采用。

## 总体架构

```text
┌──────────────────────────────────────────┐
│              competition/                 │
│  Data Adapter → Inference → Eval → JSON  │
└──────────────┬───────────────────────────┘
               │ DetectionResult
┌──────────────▼───────────────────────────┐
│              platform/                    │
│  Evidence → Alert → Review → Event → WO  │
└──────────────────────────────────────────┘
```

**两条链硬隔离**，唯一跨链接口是 `DetectionResult`（Pydantic 模型）。

## 技术栈状态

### 可以直接使用

| 技术 | 用途 | 理由 |
|------|------|------|
| Python 3.11 | 主语言 | 团队共识，数据栈兼容 |
| Pydantic v2 | 数据模型 + Schema | 类型安全、FastAPI 原生兼容 |
| pytest | 测试 | 零配置、已被验证 |
| JSON Schema | 提交格式校验 | 比赛要求 |
| Git | 版本管理 | 必然选择 |

### 技术验证（Baseline 后冻结）

| 技术 | 验证内容 |
|------|---------|
| OpenCV + FFmpeg | 视频读取、抽帧、预处理 |
| Rasterio + GDAL | 遥感读取、坐标配准、切片 |
| PyTorch + MMDetection/MMSeg | 检测/分割模型加载与推理 |
| MLflow/DVC | 实验管理、数据版本 |
| 官方基座模型适配器 | API 调用与本地加载两种模式 |

### 暂不采用（数据开放前）

| 技术 | 原因 |
|------|------|
| FastAPI / PostgreSQL | 产品链未启动 |
| React / MapLibre | 前端不抢在 Baseline 前 |
| LangGraph / 多 Agent | 初赛主链不需要 |
| RAG / 工作流引擎 | 产品 MVP 后才评估 |
| Kafka/Flink | 数据开放前不保证必要 |
| 边缘硬件 | 无实际部署需求 |

## 开源仓库审计

候选仓库按以下维度审计后记录在 `references/03_开源仓库审计/`：

- 许可证（GPL/AGPL 慎入，Apache/MIT/B SD 优先）
- 维护状态（commit 频率、issue 响应、PR 合并）
- Python 版本兼容
- 依赖的依赖（避免间接 GPL）
- 与官方基座模型的适配成本

三类结论写入此文档表格。
